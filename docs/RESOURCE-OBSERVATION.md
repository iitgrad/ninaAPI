# Resource instrumentation and October 22 observation

## Implemented limits

The plugin samples the whole N.I.N.A. process every ten seconds. The sample includes private bytes, working set, estimated live managed bytes, most recently collected GC heap/committed/fragmented bytes, cumulative allocations and CPU seconds, GC counts, handles, threads, client and pending-topic counts, retained operations, publishing/diagnostic errors, N.I.N.A. log bytes and Starfront diagnostic log bytes. HTTP diagnostics return the cached sample; opening a page does not trigger process sampling or equipment queries.

Starfront plugin diagnostics retain four files of at most 5 MiB each (20 MiB total). The gateway independently has the same 20 MiB metric budget and a 20 MiB warning/error-log budget. Rotation owns only its `metrics-N.jsonl` files. It never deletes or rotates N.I.N.A. logs. N.I.N.A. log scans stop after 1,025 entries and expose a truncation flag; an incomplete sum must not be interpreted as the full directory size. The sample reports bytes before its own append, so the next sample includes that record.

The adapter has at most eight pending topic values, eight socket clients with one waiting snapshot each, and 128 retained command records. It copies a fixed set of scalar device fields, rather than retaining arbitrary device graphs. The gateway uses one upstream socket, at most sixteen browser/CLI sockets and one pending snapshot per client. Slow senders have deadlines. The monitor retains at most 720 chart points and twelve displayed operations. These limits bound the implemented collections; they are not a cap on all N.I.N.A., driver or runtime memory.
